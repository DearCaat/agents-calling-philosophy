# llm-call.py：直接调 LLM API 的批量客户端

脚本：`scripts/llm-call.py`，只用标准库。参数、输入输出字段与默认值见 `--help`，这里不重复。

本文只写 `--help` 不说的行为、每条规则的理由，以及踩坑处。路由与凭据见 SKILL.md 第 3 节；本脚本与之不同的只有下面三条。

## 路由与凭据的差别

- 不认 `env:`、`file:` 前缀。`credential_ref` 只当变量名处理（`tool-call.py` 才认前缀）。
- `--base-url` 不查路由表，要与 `--key-env` 一起用；`--key-env` 指向一个已设置的环境变量。
- 对 127.0.0.1、localhost、::1 的请求不走环境代理。

## 思考

- 默认开启。请求里既没有 `reasoning_effort`，也没有 `thinking` 时，脚本代设一个：chat 为 `reasoning_effort=high`，Messages 为 `thinking={"type":"enabled"}`。`--no-think` 不代设；显式给的开关照发。
- 理由：漏设开关时模型会悄悄少想，质量下降却不报错，所以默认开。
- 开关名跟协议走。路由不认的字段被丢弃，不报错：开关名写错或放错协议，模型就可能不思考，而且没有任何提示。所以脚本在两种情况下打印警告：Messages 上给了 `reasoning_effort` 而没给 `thinking`；要了思考却没有任何结果带思考内容。
- 不要用 `budget_tokens`。它是思考上限，和输出上限一样会截断答案。
- `--think-limit N` 按字符计，约 3 个字符一个 token。

## 输出上限

- 默认不发输出上限，只有给了 `--max-tokens` 才发。理由：思考可以到几万 token，任何默认上限都会截掉一部分答案。
- 给了上限后结束原因为长度用尽的，记为失败，不当结果收下。这类失败的 `error` 以 `truncated` 开头，并提示调大或去掉 `--max-tokens`。
- 答案不空却被截断的，不重发：同样的上限会再截断一次。答案为空且结束原因为长度的，按思考失控处理（见下）。
- 坚持要上限的路由（Anthropic 官方）回 400；400 信息里含 `max_tokens` 时，脚本提示加 `--max-tokens`。

## 超时与重试

- 默认流式接收。`--no-stream` 时 `--idle-timeout` 与 `--think-limit` 不起作用，`--timeout` 同时成为读取超时。
- 等待超过 120 秒才返回的 408、504、524 不重发，记为失败。理由：同一请求还会等满同样的上限。120 秒内返回的，按可重试处理。
- 可重试的 HTTP 状态：408、409、425、429、500、502、503、504、520、522、524、529。网络错误、非 JSON 回包、回包带 `error`、无内容、流未给结束原因，也都重试。其他 HTTP 错误（如 400、401、403、404）不重试。
- `Retry-After` 为数字且不超过 120 秒时按它等；否则从 2 秒起、每次翻倍、上限 60 秒，并加随机抖动。

## 思考失控

- 指输出上限已到而答案为空，或流式思考超过 `--think-limit`。
- 只在同一路由重发（`--runaway-retries`，默认 1），不换路由。理由：思考失控多是个别事件，重发一次即可；换路由可能同时换计费与模型，不该为一次个别事件付出。

## 并发与预热

- `-j` 大于 1 时，先串行发前 `--warmup` 条，再并发发其余。
- 理由：厂商要先见过一个前缀才会存下它，同时发出的请求会一起落空。例如 DeepSeek 从第三次请求起持久化前缀，Anthropic 在首个响应开始后。
- 连续失败的条目达到 `--stop-after-failures` 时，停止发起新请求。若某条路由反复限流、超时或触发连续失败停机，在核对已授权通道清单（`api-routes.tsv` 与备注）及并发上限后改走备用路由，不在同一受阻通道上死等（单个条目的思考失控则仍按上节只在同路由重发一次）。

## 缓存

- 缓存相关的参数（`--session-id`、`--cache-system`，以及默认的 `X-Session-ID`）见 `--help`。
- 网关怎么认 `X-Session-ID`，见网关文档「会话粘性」。
- 固定内容放前、前缀逐字一致的通用道理，见 research-foundation 插件的 `delegating` 技能（`references/executors.md`）。

## 退出与日志

- 启动与结束各打印一段摘要；每个失败条目在标准错误打印 id、尝试次数和错误。
- 退出码：0 没有失败、也没有未发起的条目；1 有失败或有未发起的条目；2 参数或输入有错（如 `id` 重复）。

## Gemini 不经本脚本

Gemini 不走本脚本（2026-10-25 本机所有者定，账号安全）；脚本不检查模型名，这条只靠使用者遵守。走哪个入口见入口表。

## 与 tool-call.py 的分工

- 批量分类、筛选、打分先在 `tool-call.py jev` 上调优问法、选项和输入（如切图、局部上下文），实测精召仍不达标时再升级到本脚本；`jev`、`vela` 及 `mineru`、`oxr` 均走 `tool-call.py`，用法见 `references/tools.md`（旧的 `jev-call.py` 仍可用，内部转调 `tool-call.py jev`）。
- 除上节「Gemini 不经本脚本」等文档明确列出的例外外，所有直接调 LLM API 的批量调用统一走 `scripts/llm-call.py`，不另写平行封装或自建请求循环，以保留默认思考开关、前缀预热、流式空闲超时与断线续跑保护。
